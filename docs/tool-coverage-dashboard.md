## Ledger Classification Notes

- Live protocol/recovery coverage is intentionally broader than live happy-path coverage. Optional paid-feature domains may still return recovery when the workspace plan or permissions do not allow the operation.
- Remaining live protocol/recovery yes + happy-path no rows are classified as intentionally recovery-only when they are destructive, externally noisy, or stateful beyond created test entities; needs-domain-gate when they require a real approval/user-admin lifecycle beyond this campaign; and unavailable-paid-feature when the live API or workspace plan has not exposed a safe success route.
- Three scheduling OpenAPI paths are uncovered by design: `PUT /scheduling/assignments/series/{id}` (the `ALL` series_update_option on update covers the same intent), `POST /scheduling/assignments/{id}/copy` is raw-fallback-only: it has no dedicated typed tool and is reachable via `clockify_api_request` (`method:"POST"`, `path:"/workspaces/{workspaceId}/scheduling/assignments/<assignmentId>/copy"`, with `CLOCKIFY_ENABLE_RAW_WRITES=true`) because a typed tool would break the fixed 156-tool registry and its request body is not verified against a live workspace, and `POST /scheduling/assignments/user-filter/totals` (overlaps the existing scheduling user-totals tools).
